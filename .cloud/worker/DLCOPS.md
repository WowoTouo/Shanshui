## 1. DLC 机制（记忆驱动的技能扩展）

**本质**：AI 根据每天的经验，给自己"装技能包"——追加提示词优化工作流。这是受控进化的正式形态。

### 目录结构
```
/home/agent/dlc/
  ├── 001-<技能名>.md      # DLC 本体（提示词扩展包）
  ├── 002-<技能名>.md
  └── archive/             # 过期/失效 DLC 归档（不删除，留痕）
```

### 规则
1. **谁能写**：只有 AI 自己，在每天写总结时评估——今天遇到的经验是否值得固化成 DLC（新技能 / 新规则 / 工作流优化 / 坑的预防）。
2. **怎么写**：每个 DLC 一个文件，编号递增，格式：
   ```markdown
   # DLC 001 · <技能名>
   触发: <什么场景用>
   内容: <给未来自己的提示词/规则/步骤，≤200字>
   来源: <哪天哪件事的经验>
   ```
3. **何时注入**：worker.py 启动时按编号顺序读取 dlc/*.md 全部注入 system prompt（紧跟 PROMPT.md 之后）。
4. **上限防失控**：
   - 总数 ≤20 个；超出 → 合并/归档旧的进 archive/
   - 单文件 ≤200 字；超过 → 精简
   - **DLC 不得覆盖安全边界**：权限/凭据/黑名单/系统配置相关条款，DLC 写了也无效（worker.py 加载时过滤含"权限/凭据/黑名单/重启"关键词的 DLC 内容，或仅作建议不生效）
5. **过期管理**：连续 14 天没被触发逻辑用到的 DLC，建议归档（AI 自己判断）。

## 2. 日报协议（每天 08:00，省性能版）

- **时间**：每天 **08:00**（总结"昨天 08:00 → 今天 08:00"）——注意是 08:00，不是 06:00。
- **模板填空，不自由写作**（省 token）：
```markdown
# 日报 YYYY-MM-DD
简述: <今天主线干了什么，≤1句>
修复: <修了什么 bug/问题，≤3条，每条≤10字>
解决: <解决了什么问题，含解法卡编号>
推进: <项目进度状态>
DLC: <今天新增/归档的 DLC 编号>
清理: <今天空闲清理了啥>
明日: <明天方向，≤1条>
```
- 落盘：`/home/agent/memory/daily/YYYY-MM-DD.md`；同时并入长期记忆索引。
- 邮件：日报邮件照发（内容同模板）。

## 3. 空闲自动清理（不频繁、不烧积分、不碍进程）

**原则：只在"任务做完停下来的空闲窗口"清理，不单独为清理跑调度；间隔 ≥6 小时才允许再清。**

### worker.py 内置清理触发器（v3.7）
```
主循环回到空闲状态（无待处理任务，准备 sleep 60 前）:
  if 距上次清理 ≥6h 且 无积压任务:
      触发 cleanup.sh（子进程，超时 120s，失败不阻塞主循环）
      更新上次清理时间戳
```

### cleanup.sh 清理范围（白名单式，只清这些）
| 清 | 不清 |
|---|---|
| /tmp 下 >1 天旧文件 | .env（600） |
| __pycache__ / .pyc 缓存 | ONBOARDING.md / PROMPT.md / DLC/ |
| work/ 下 >7 天且非保留清单的中间文件 | work/learnings/、work/tools/、work/templates/ |
| 日志轮转（已有 logrotate 保留 14 天） | tasks/、done/（归档区） |
| git 临时文件（.git 内 gc 自动处理） | memory/（记忆区） |

- **先 dry-run 列清单**（前 2 次手动确认），确认后转自动。
- 清理是子进程：**绝不 kill / 干扰 worker 主进程**；失败仅记日志，不影响任务执行。

## 4. 开机自启动自检（每天醒来 30 秒）

worker 启动时自动执行（脚本 `/home/agent/work/tools/bootcheck.sh`）：
1. .env 可读（600）→ 2. DLC 目录加载 → 3. 任务队列无异常积压 → 4. 磁盘 <85% → 5. 日志无连续 ERROR → 6. 有 PROJECT 未完成 → 读 PLAN.md 续作；无 → 空转。
- 自检结果：1 行写入当日日志，不单独汇报（除非异常）。
