# 任务：部署 DLC 机制 + 日常运转协议（worker v3.7）
优先级：高

## 背景
总工下发 DLC 体系：核心提示词固定（缓存命中），DLC 扩展层可挂载。
官方首卡 DLC-001 定义：每日 8 点总结 / 自动清理循环 / 权限提案通道。

## 一、DLC 挂载机制（worker.py）
1. 建 `/home/agent/dlc/`，放入 DLC-001-daily-operations.md（总工提供）
2. worker.py 启动时：读取 dlc/*.md（按文件名排序）拼进 system prompt（追加在 PROMPT.md 之后，启动读一次，静态保持）
3. 挂载顺序：PROMPT.md → ONBOARDING.md → AUTONOMY.md → dlc/*.md

## 二、每日 8 点总结定时器
1. agent 用户 crontab 添加：`0 8 * * *` 生成每日总结任务卡进 tasks/（worker 自动领取执行）
2. 任务卡内容按 DLC-001 §1 五元素格式（简述/修复/解决/推进/沉淀，≤200 字）
3. 验证：crontab -l 可见；手动跑一次任务卡验证产出格式

## 三、清理循环落地
1. 写 `/home/agent/work/tools/cleanup.sh`：
   - 范围：/tmp >24h、work/ 下 >7 天非保留且已上传的中间产物、logs 保留 14 天、功能性缓存
   - 保留清单：.env、*.md、learnings/、tools/、tasks/、done/、memory/、源码配置
   - **默认 dry-run**：输出清单到 logs/cleanup-dryrun-<日期>.md，不直接删
   - 独立子进程执行，不影响 worker 主进程
2. worker.py 空闲转 sleep 时触发清理检查（每天上限 1 次，零 token——脚本不经过模型）
3. 首次只 dry-run 出清单汇报总工，批准后自动执行

## 四、提案通道就位
1. 建 `/home/agent/proposals/`（已存在则确认）
2. 邮件模板：标题 `[权限提案]` + 正文引用提案文件路径（AI 只发通知，不自行启用）
3. worker.py 检查 proposals/ 新文件时邮件通知用户

## 五、验收
1. 重启 → 日志确认 dlc 加载（DLC-001 在列）
2. 挂载验证：AI 能答出 DLC-001 三条机制（8 点总结/清理/提案）
3. crontab 就位 + cleanup.sh dry-run 出清单
4. 全部提交 git，汇报：日志关键行 + dry-run 清单摘要 + crontab 输出

## 参考（总工侧已就绪的素材，服务器 AI 可对照实现）

- cleanup.sh / daily-card.sh / send-result-mail.sh：总工侧 `.cloud/worker/` 下
