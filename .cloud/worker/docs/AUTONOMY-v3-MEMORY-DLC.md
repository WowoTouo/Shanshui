## 1. 日报协议（每天 08:00，低开销）

- **时间**：每天 08:00（总结"昨天 08:00 → 现在"24 小时滚动）。
- **低开销原则**：日报**不重新推理**——从 PLAN.md / result.md / 日志直接汇总，便宜档生成，≤150 token。
- **模板**（固定）：
  ```markdown
  # 日报 YYYY-MM-DD (08:00)
  简述: ≤3 行（主线做了什么）
  修复: 问题 → 解法卡#N（无则"无"）
  解决: 达成的结论/里程碑
  推进: 当前项目状态 / 下一步
  DLC: 新增/更新 DLC-<编号>（无则"无"）
  ```
- 存 `memory/daily/YYYY-MM-DD.md`，同时邮件发送。

## 2. DLC 技能扩展机制（AI 给自己加技能包）

- **目录**：`/home/agent/dlc/`，文件 `DLC-<编号>-<短名>.md`。
- **AI 何时写 DLC**：日报时，若当天经验里有"可复用的工作流技巧/踩坑规律/高效写法" → 写或更新 DLC。
- **格式**（≤500 字）：
  ```markdown
  ## DLC-<编号> · <技能名>
  场景: <什么时候用>
  提示词: <可直接注入的指令片段，一段话>
  来源: <哪天的什么经验>
  ```
- **加载**：worker 启动时按编号顺序加载全部 DLC，拼在 system prompt 末尾。
- **防膨胀**：总数 ≤20；超限 → AI 合并同类/废弃旧卡（废弃的移入 `dlc/archive/`）。更新频率 ≤1 次/天（缓存失效成本一天一次，可接受）。
- **原则**：DLC 只能优化"怎么干活"，**不能改"边界"**（权限/黑名单/铁律永远不进 DLC）。

## 3. 空闲清理协议（低频、不打扰、不浪费积分）

- **触发**：worker 空闲循环（无任务 sleep 时）每小时检查一次：距上次清理 >24h 且当前空闲 → 触发。
- **清理范围**（自动执行，仅安全项）：
  - `/tmp` 过期文件
  - pip cache（`~/.cache/pip`）
  - gradle 缓存旧版本（`~/.gradle/caches` 保留最新）
  - work/ 下 >7 天且已上传 GitHub 的中间产物（保留清单外的）
- **安全**：保留清单（.env/ONBOARDING/PROMPT/AUTONOMY*/dlc/learnings/tasks/done/logs/memory）绝不删；首次只 dry-run 列清单进日志，人工确认后自动执行；清理脚本超时 120s 保护，失败不阻塞主循环。
- **脚本**：`work/tools/cleanup.sh`（幂等、可 dry-run、日志留痕）。
- **原则**：每天最多 1 次，绝不频繁；清理是后台动作，不影响 AI 进程与任务。

## 4. 权限升级通道（AI 申请，总工批准）

- AI 想要更多权限 → 写 `proposals/UPGRADE-<主题>.md`：
  ```markdown
  ## 权限升级申请 · <主题>
  想要: <具体权限/命令/目录>
  为什么: <任务需要>
  风险: <自我分析>
  最小授信: <建议的最小范围>
  ```
- **AI 绝不自行改权限**——只申请；总工（用户侧 AI）批准后由总工改 sudoers/白名单。
- 拒绝/搁置 → 归档 proposals/archive/，AI 继续在现有权限内想办法。
