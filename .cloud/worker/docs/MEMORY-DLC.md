## 1. 每日总结（每天早上 08:00，最小开销）

**时间**：每天 08:00 自动执行，覆盖「昨天 08:00 → 今天 08:00」时段。
**文件**：`memory/daily/YYYY-MM-DD.md`
**格式（固定模板，极简，每项 ≤1 行，不展开）**：

```markdown
# YYYY-MM-DD 总结
时段: MM-DD 08:00 → MM-DD 08:00
简述: <今天整体在干什么，一句话>
修复: <修复的问题，引用解法卡编号如有>
解决: <攻克的关键点>
推进: <项目进度前进到哪>
明日: <下一步方向一句话>
```

**开销控制（铁律）**：
- 只读日志摘要 + done/ 结果文件标题，**不重读全部产物**
- 细节不展开——已在解法卡/learnings 的，只写编号引用
- 生成耗时目标：<1 分钟，<500 tokens
- 生成后追加进长期记忆（memory/），邮件日报同步 08:00 发出（极简版，纯文本，≤10 行）

## 2. DLC 机制（记忆驱动的技能扩展）

**是什么**：AI 根据一天的经验，自己写"技能模块"（DLC），优化自己的工作流。像游戏 DLC——随时可加、模块化、不污染核心。

**目录结构**：
```
memory/dlc/
├── INDEX.md          ← 索引（AI 自动维护）
├── 001-<技能名>.md
├── 002-<技能名>.md
└── ...
```

**DLC 格式（每卡 ≤40 行）**：
```markdown
# DLC-<编号> · <技能名>
适用场景: <什么情况下用>
触发条件: <看到什么就想到用它>
优化步骤: <改进后的工作流，可直接执行>
示例: <1 个真实案例>
来源: <哪天的经验沉淀，引用总结/解法卡>
```

**生成时机**：每日 08:00 总结时，自查：今天是否遇到"可复用但当前工作流没覆盖"的经验？
- 有 → 写新 DLC 或更新旧 DLC → 更新 INDEX.md（编号/名称/适用场景）
- 无 → 不写（不为了写而写，控制体积）

**加载规则（关键，防膨胀）**：
- DLC **永不常驻 system prompt**（会撑大前缀、破坏缓存命中）
- PROMPT.md 只注入一条规则："遇到新场景先查 `memory/dlc/INDEX.md`，命中则读对应 DLC 再执行"
- 每次需要时按需读文件——DLC 是外置技能，用时才加载

**DLC 分类建议**：工作流优化 / 研究技巧 / 工具脚本 / 报告格式 / 性能与额度 / 排查套路

## 3. 三层知识体系（越干越熟，互不重复）

| 层 | 文件 | 粒度 | 何时用 |
|---|---|---|---|
| 核心提示词 | PROMPT.md | 身份/协议/边界（静态） | 永远在（缓存命中） |
| 解法卡 | learnings/solutions.md | 具体问题快解（30 秒套用） | 遇到报错/症状 |
| DLC | memory/dlc/*.md | 技能模块（工作流级） | 遇到新场景/要优化流程 |

## 4. 进化闭环（每天转一圈）

```
08:00 总结（四元素）
  → 发现问题解法 → 写解法卡
  → 发现可复用工作流 → 写/更新 DLC + INDEX
  → 明日方向 → 写入总结
→ 白天执行时：先查 INDEX/DLC → 套用技能 → 更快更好
→ 晚上又是新经验 → 明天继续沉淀
```

**本质**：每天 8 点的总结不是"汇报"，是 AI 的**自我进化仪式**——把一天的经验固化成知识资产，越干越熟，额度越用越省。
