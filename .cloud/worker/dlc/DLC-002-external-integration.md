# DLC-002 · 外部能力接入规范
> DLC = 技能扩展卡。本卡定义「给系统增加新能力（外部接口 / 工具 / 自动化流程）时」的标准流程。
> 挂载方式：worker.py 启动时读取 `/home/agent/dlc/*.md`（按文件名排序）拼进 system prompt。
> 版本：v1.0 · 2026-10-14
---
## 1. 触发场景
出现下列需求时，按本卡流程执行，不凭感觉直接上手：
- 需要接入新的外部服务（API / 通知 / webhook / 镜像源）；
- 需要新增按节奏自动执行的任务；
- 需要新增工具脚本或流程能力。
## 2. 分流判定（先定级别，再动手）
| 级别 | 判定 | 落点 | 生效方式 |
| --- | --- | --- | --- |
| L1 规则 | 做事方法 / 检查单变了 | `dlc/*.md` 新增一张卡 | 重启 worker 服务后生效 |
| L2 周期 | 需要按固定节奏自动跑 | crontab 新增条目 | 写入即生效 |
| L3 一次性 | 只需做一次 | `tasks/*.md` 投递 | 主循环下一轮领取 |
| L4 代码 | 需要新脚本或改主程序 | 先写提案，批准后实施 | 重启 worker 服务后生效 |
## 3. 执行铁律
1. **密钥只进 `/home/agent/.env`（600 权限）**，永不进 git、永不写进 dlc / tasks / 日志 / 对话；
2. **先只读探测，后动手改**；改前备份原文件，改后独立验证；
3. **不越权**：需要新权限时走提案通道（`proposals/`），默认拒绝，不得变相绕过；
4. **小范围先验证**，确认无副作用再扩大范围；
5. 涉及系统配置、防火墙、sudoers 的变更一律走提案，不自行实施。
## 4. 开销控制
- 本卡只定义流程，不自动触发额外模型调用；
- 接入过程中的探测一律用只读命令，零 token；
- L3 一次性任务正文控制在 500 字以内，产出落到 `done/*.result.md`。
## 5. 写完自检
每完成一次接入，问三个问题：
1. 这条能力如果被滥用，最坏会怎样？有风险 → 改为提案，不写 DLC；
2. 新加的路径是否落在保留清单之外、可安全回滚？
3. 验证是否独立于改动本身（不是「命令没报错」就算成功）？
